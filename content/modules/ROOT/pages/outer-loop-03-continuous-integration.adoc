[sidebar]
.Continuous Integration
--
So far you have been building each service manually to OpenShift. Although
it's convenient for local development, it's an error-prone way of building software if
extended to test and production environments.

Continuous Integration (CI) is a phase in the software development cycle where code from different team members
or different features are integrated together. This usually involves merging code (integration),
building the application (container) and carrying out basic tests all within an ephemeral environment.

OpenShift simplifies building CI/CD Pipelines by integrating Tekton into
the platform and enables defining truly complex workflows directly from within OpenShift.
--

[#what_is_openshift_pipelines]
== What is OpenShift Pipelines?

[sidebar]
--
image::tekton-logo.png[Tekton,300]

OpenShift Pipelines is a cloud-native, continuous integration and continuous delivery (CI/CD) solution
for building pipelines based on the https://tekton.dev/[Tekton^] project.

* Standard CI/CD pipeline definition based on Tekton
* Build images with Kubernetes tools such as S2I, Buildah, Buildpacks, Kaniko, etc
* Deploy applications to multiple platforms such as Kubernetes, serverless and VMs
* Easy to extend and integrate with existing tools
* Scale pipelines on-demand
* Portable across any Kubernetes platform
* Designed for microservices and decentralized teams
* Integrated with the OpenShift Console

https://tekton.dev/[Tekton^] provides Kubernetes-style resources for creating serverless
CI/CD-style pipelines on Kubernetes.

The custom resources needed to define a pipeline are:

* **Task** - a reusable, loosely coupled number of steps that perform a specific task (e.g., building a container image)
* **Pipeline** - the definition of the pipeline and the **Tasks** that it should perform
* **TaskRun** - the result of running an instance of **Task**
* **PipelineRun** - the result of running an instance of **Pipeline**, which includes a number of **TaskRuns**

Tasks and Pipelines receive their inputs (e.g., the URL of a Git repository or the name of the image to build) as **Parameters**,
and share files (e.g., the cloned source code) through **Workspaces**, which are backed by storage such as a PersistentVolumeClaim.

OpenShift Pipelines ships ready-to-use Tasks maintained by Red Hat, such as `git-clone`, `s2i-java` and `openshift-client`.
They live in the `openshift-pipelines` namespace, and your Pipelines reference them through the cluster resolver.

image::tekton-architecture.png[Tekton Architecture,600]

[#create_pipeline]
== Create a Pipeline

A **Pipeline** defines a number of **Tasks** that should be executed and how they interact
with each other via **Workspaces**. Let's define and configure these different components.

In the link:{CONSOLE_URL}/topology/ns/{STAGING_PROJECT}[OpenShift Console^],
`*click on 'Pipelines' -> 'Pipelines', then on 'Create' -> 'Pipeline'*`.

image::openshift-create-pipeline.png[OpenShift - Create Pipeline,800,link=self,window=blank]

In the "Pipeline builder" page, `*specify 'inventory-pipeline' as Name*`

image::openshift-add-pipeline-name.png[OpenShift - Pipeline Name,400,link=self,window=blank]

`*Scroll down to the 'Workspaces' section and define a Workspace called 'shared-workspace'*`

image::openshift-add-pipeline-workspace.png[OpenShift - Pipeline Workspace,600,link=self,window=blank]

`*Scroll up to the 'Tasks' section, then click on 'Add task'*`.

image::openshift-add-pipeline-task.png[OpenShift - Add task,600,link=self,window=blank]

`*Start typing 'git-' next to the (+) and select 'git-clone'*`.
There are several options to choose from, look out for the *Red Hat* one. `*Then click on 'Add'*`.

image::openshift-add-git-clone-task.png[OpenShift - Add Git Clone Task,500,link=self,window=blank]

`*Click on the newly created 'git-clone' task and enter the following configuration*`:

.git-clone Task
[%header,cols="30%,70%"]
|===
|Parameter
|Value

|Display Name
|git-clone

|URL
|pass:a[{GITEA_INTERNAL_URL}/{OPENSHIFT_USERNAME}/inventory-quarkus.git]

|REVISION
|main

|Workspaces output*
|shared-workspace

|===

Once done, let's add another task. `*Click on the blue plus icon at the right hand side of the 'git-clone' task*`

image::openshift-add-task.png[OpenShift - Add task,500,link=self,window=blank]

`*Then click on 'Add task'*` and, as before, `*type 's2i-java' next to the (+)*`. When you see the *Red Hat* one, `*select and add the 's2i-java' task*`.

`*Click on the newly created 's2i-java' task and enter the following configuration*`:

.s2i-java Task
[%header,cols="30%,70%"]
|===
|Parameter
|Value

|Display Name
|s2i-java

|IMAGE*
|image-registry.openshift-image-registry.svc:5000/{STAGING_PROJECT}/inventory-coolstore

|VERSION
|openjdk-21-ubi9

|CONTEXT
|. _(dot, the default value)_

|ENV_VARS (+Add values)
|MAVEN_MIRROR_URL=pass:a[{MAVEN_MIRROR_URL}]

|TLS_VERIFY
|false

|Workspaces source*
|shared-workspace

|===

[NOTE]
====
`VERSION` selects the Java builder image (`openjdk-21-ubi9`, Java 21) and `CONTEXT` is the folder of the application within the cloned repository.
`MAVEN_MIRROR_URL` points the Maven build to the Maven mirror of the workshop to speed up the download of the dependencies.
====

Once done, `*click on 'Create'*`. Your simple Pipeline is now created.

image::openshift-ci-pipeline.png[OpenShift - CI Pipeline,700,link=self,window=blank]

[#run_pipeline]
== Run the Pipeline

Now that your pipeline is created and configured, let's run it.

In the link:{CONSOLE_URL}/topology/ns/{STAGING_PROJECT}[OpenShift Console^], `*click on 'Pipelines' -> 'Pipelines' -> 'inventory-pipeline' -> 'Actions' -> 'Start'*`

image::openshift-start-inventory-pipeline.png[OpenShift Start Inventory Pipeline,900,link=self,window=blank]

`*Enter the following parameters, then click on 'Start'*`

.Pipeline Parameters
[%header,cols=2*]
|===
|Name
|Value

|shared-workspace
|VolumeClaimTemplate

|===

The *VolumeClaimTemplate* creates a new PersistentVolumeClaim for each run of the pipeline, which the Tasks use to share the cloned source code.

image::openshift-inventory-pipeline-parameters.png[OpenShift Inventory Pipeline Parameters,600,link=self,window=blank]

Congratulations! You have created and run your first **CI Pipeline on OpenShift**!
